## I. Compatibilidade e bloqueadores

`verify_build.py` valida origin exato, SHA Git completo, classes Java 21,
ausência de harness no pacote, testes/cobertura, plataforma/usuário/entrypoint,
JAR da imagem e checksums. `target/build-evidence.json` registra base_revision,
dirty, hash do diff e hash das fontes locais, sempre state=local_review_only e remote=null.
Compatibilidade adicional a revisar na Infra: o builder 9.2.5-B usa Docker
com network=none. Um builder limpo, mesmo com as bases disponíveis, precisa
de cache/camadas Maven previamente preparados para esses Dockerfiles.
Nesta etapa a resolução autorizada ocorreu no Maven Central, não na AWS.
Preparar o cache explicitamente ou revisar a política de egress Maven do futuro
builder é uma dependência da integração; o validador Infra não foi alterado.
Esse recibo diagnóstico **não substitui** o recibo produzido pelo mecanismo
da Infra nem pode promover artefatos a publicados/aprovados.
Enquanto houver mudanças sem commit, a identidade é revisão-base + árvore local,
não um novo commit verificável. Após revisão e commit pelo proprietário, executar
o builder 9.2.5-B com fontes limpas e SHA completo para gerar seu recibo próprio.
Bloqueadores restantes: versionar as correções após revisão e configurar SonarQube.
Os gates ECR/S3/Lambda e os ambientes demo-a/demo-b não foram alterados.

Em árvore limpa, acrescentar ao build o label
`--label org.opencontainers.image.revision="$(git rev-parse HEAD)"`.
Em árvore modificada, não declarar o SHA-base como identidade exata da imagem.
Pré-requisitos: Java 21, Maven, Python 3 e Docker Linux/amd64; dependências Maven
aprovadas/cache, imagens de teste e bases fixadas disponíveis. Falta de dependência
bloqueia a execução, sem desabilitar testes. Foram executados sete testes unitários
do verificador por repositório e verificação de sintaxe Python, além dos testes Maven.
O resumo de testes é exclusivamente diagnóstico, inclusive com falhas ou relatórios
ausentes; não substitui o gate estrito, não aprova build e não publica artefatos.
O smoke requer as imagens públicas PostgreSQL/MongoDB/RabbitMQ/Python correspondentes.
Sem Secrets reais ou rede AWS; imagens/artefatos não são publicados.
